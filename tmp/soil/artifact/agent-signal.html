Tier sizing for the KR

Nour's three tiers, measured from every user message and the agent's next reply. Tier 1 is an upper bound: it counts replies that didn't refuse or fail, but there's no signal yet that the user's problem was actually solved (thumbs-up/down feedback is empty for every message stored).

How this answers the methodology questions in the kickoff thread

JJ suggested three ways to find what the chat must support, and the thread asked for three KPIs: answered and not deflected, answered accurately, answered on time. Here is what this pack covers and what is still open.

JJ's three suggestions

  • 1 · Mine past incidents for likely questions. Covered from a better source Instead of guessing questions from incidents, this pack reads the 21,810 questions people actually typed (3,165 users, 6 surfaces) and pairs each with the agent's final reply. The manual-action table adds what people do by hand in incidents, alerts and shifts. Not done: reading retro and timeline text for questions nobody has asked the agent yet.
  • 2 · Generate hundreds of persona prompts with Claude and test which ones the chat handles. Half there A harness already exists: the golden set runs 894 cases across 38 scenarios. It is organized by tool, not by persona or question, and it skips the high-handback intents above. Next step: generate about 300 persona prompts, seeded from the intents and repeat handbacks in this pack, add them as golden-set scenarios run per surface (web read-only vs Slack), and score them with the same tier rules. That run becomes the KR's offline measurement.
  • 3 · Collect the really hard ones ourselves and from customers. Seed ready The 948 repeat handbacks from 208 users are the hard set customers already found. Sample them by intent, strip identifiers and add them to the eval dataset.

The KPIs in the thread

  • X% answered and not deflected: Tier 1, 89.8% overall (an upper bound) and 72% on web. It comes from reply text, so a structured refusal tag is the next step.
  • Y% answered accurately: no production signal Feedback is empty everywhere. The only production proxy: 48 of 2,112 follow-ups open with an explicit correction. Golden-set scores would give an offline accuracy number, but this lane can't read them.
  • Z% answered on time: time to final reply is 8.8s p50 and 37s p95. Model-level latency is in Braintrust traces, which this lane can't read.
  • One brain, many surfaces: every tier is split by surface. Slack carries 78% of asks, so a homepage target should be read next to Slack's 9.0%.

Methodology

  • Population: sessions in ai_sessions created in the last 180 days (May 16 – Nov 12, 2026). ai_session_messages holds no message text before Aug 2 (56 messages in Jun–Jul), so ask-level numbers cover Aug 2 – Nov 12. for teams with paying_customer, not sandbox, not deleted. Tier, intent and prompt analysis excludes the background surfaces ai_sre_memory, automation and admin_kg.
  • Unit: each user message in ai_session_messages, paired with the agent's final text reply in that turn: the last assistant message before the user's next message. About 70% of stored assistant messages are JSON tool-call records, so those are skipped. (An earlier version of this page paired each ask with the next assistant message, which was often a tool call. That understated handbacks: 5.3% instead of 9.4%.)
  • Tier 3: no final text reply, an error reply ("something went wrong", "timed out"), or can't-do wording ("I can't", "I don't have a tool", "read-only", "I'm unable to"…). Data misses ("can't find/see/access") are excluded. On a 50-message hand sample, the refusal rule was right 41 times (≈80% precision); recall was not measured.
  • Tier 2: the reply links docs.rootly.com or the help center, or tells the user where to go in the app, and does not refuse.
  • Tier 1: everything else. It's an upper bound on resolution.
  • Latency: time from a user message to the agent's final text reply in that turn.
  • Correction proxy: of 2,112 cases where the user wrote again after a reply, 48 open with an explicit correction ("no", "that's wrong", "didn't work"). It's a weak signal and isn't used in the tiers.
  • Guardrails: the canned off-topic decline appeared 75 times (46 teams), 3 of them right after an action request. The empty-context decline never appeared on chat surfaces.
  • Intents and PRD prompts: keyword and regex rules on lowercased text. They are heuristics: buckets like "Shift cover & handover" also catch messages that mention shifts in passing.
  • Manual actions: alert_events (kind action/status_update with a user), incident_events (user-attributed status kinds), incident_role_assignments, shift_coverage_requests, shift_overrides, incident_action_items. Home-chat capability is from app/services/ai/tools/home_write_allowlist.rb and the tools' home_chat_write declarations.

Data gaps

  • Braintrust: metadata only. Project and experiment metadata is readable, and it is used in the eval-coverage section above. Every trace or score read (sql_query, infer_schema, summarize_experiment, project settings) was refused by this lane's integration hook as not read-only, including retries on 2026-11-12. So there are no golden-set pass rates, trace-level intents, model latency or token cost here, and none have been estimated. The coverage map assigns golden-set scenarios to intents by name.
  • Homepage traffic by persona: not reproduced. ahoy_events in Main DB has no rows for the last 30 days, and no Metabase card for homepage page views was found. The PRD's 27.8k views / 30d and 23% of active users could not be checked.
  • No resolution signal. feedback_sentiment is empty for all messages in the window, so Tier 1 can't be split into "resolved" and "answered but not helpful".
  • Home chat has almost no volume yet (about 67 sessions, 2 teams, per the earlier lane report), so it can't serve as a baseline for the new surface.
  • No structured refusal tag. Tier 3 and intents come from text rules, so they are approximations.
  • Six months of asks isn't available. About 150k sessions were created since May, but stored message text starts Aug 2, so the tiers cover 14 weeks. Older asks may exist in Braintrust traces, which this lane can't read.
  • Mixed windows in the manual-action table (7-day alerts, 30-day incidents and shifts) are normalized to a weekly rate. Incident and shift counts include every team, not just paying ones.
  • Alert-action counts over 30 and 90 days timed out in Metabase, so alert actions use the last 7 days only.

No customer names or personal data are shown. All figures are aggregates from Metabase queries run on 2026-11-12.
